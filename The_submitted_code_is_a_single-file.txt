The submitted code is a single-file partial prototype that implements only the RL (Q-learning) detection component. It operates in the correct domain (vehicular networks, VeReMi dataset) and captures the general algorithmic idea, but suffers from:
	The supervised grid-based classifier is missing (and that is the paper's headline contribution, F1 = 0.996).
	Discrepancy (different hyperparameters) between the code and the paper's stated experimental setup.
	Fundamental decision logic mismatch where the Q-learning score is computed but not actually used for classification.
	Missing training methodology (no 500-episode training, no train/test split).
These issues mean that no reader or reviewer can run the provided code and obtain the results reported in the paper. 
This constitutes a reproducibility concern that must be resolved.

Issue 3: Decision Logic Mismatch — Q-Learning Score Not Used for Classification
Paper Describes (Section IV-F)
The paper explicitly defines the detection mechanism as score-based:
"Score" (v_i )=Q(s_low,stay)-Q(s_high,stay)-Q(s_high,switch)
"Decision:" v_i={■("benign" ,&"if Score" (v_i )>θ@"malicious" ,&"otherwise" )┤
Code Implements (lines 178-184)
score = q[("low", "stay")] - q[("high", "stay")] - q[("high", "switch")]
predicted_malicious = False
if state == "high":
    predicted_malicious = True      # Cluster-based: ALWAYS malicious
elif state == "low":
    predicted_malicious = False     # Cluster-based: ALWAYS benign
else:
    predicted_malicious = score <= threshold   # Score only used when state is None
Concern
The code computes the score formula but does not use it for classification. Instead, it performs a naive cluster-based decision: if the vehicle is currently in the "high" cluster, it is malicious; if "low," it is benign. The score/threshold mechanism is only a fallback for the edge case where cluster state is uninitialized.
This means the Q-learning update has no influence on the final detection output. The Q-table is trained but its learned values are never consulted for the decision. The detection is effectively just raw k-means clustering with no reinforcement learning benefit.
This raises a fundamental question: do the paper's reported accuracy curves (Figures 5-8) actually reflect Q-learning-based detection, or do they reflect simple clustering? If the latter, the paper's claims about RL-driven adaptability are unsupported.
Required Action
	Correct the decision logic to use Score(v_i) > θ as the primary classification rule, as described in the paper.
	Re-run experiments with corrected logic and verify accuracy curves still hold.
	If the curves were generated with the cluster-based decision, the paper must be revised to accurately describe the actual detection mechanism.

Issue 4: No Multi-Episode Training or Train/Test Split
Paper States (Section VI)
"The Q-learning agent was trained for 500 episodes using the standard VeReMi train/test split convention adopted in prior work, where 70% of the traces are used for training and 30% for testing."
Code Reality
The code performs a single sequential pass over all BSMs in a scenario. There is:
	No concept of "episodes" or repeated training passes
	No splitting of data into training and testing subsets
	No separate training phase followed by evaluation
	No mechanism to iterate through data multiple times
The accuracy is computed cumulatively over the single pass.
Concern
500 episodes of training allows Q-values to converge toward stable policies. A single pass provides minimal learning opportunity. The accuracy curves in the paper almost certainly cannot be reproduced from a single-pass approach — yet that is all the code implements.
Required Action
	Implement the 500-episode training loop with 70/30 split as described.
	Show that Q-values converge over episodes.
	Demonstrate that the reported accuracy curves (Figures 5-8) emerge from this training procedure.
