Subject: Response to Reviewer Comments and Resolution of the Six Issues

Dear Reviewer,

Thank you for your detailed review and for highlighting the six issues related to reproducibility, method completeness, and alignment with the paper. We have carefully addressed each of them in the revised repository and accompanying manuscript.

1. Supervised Grid-Based Method
We implemented a complete supervised grid-based detector in the file veremi_supervised_grid_detector.py. This new component constructs the n x n grid from VeReMi position data, extracts the grid-based features described in the paper (including the seven grid-derived features plus average speed), trains a supervised classifier, and evaluates multi-class detection across the five VeReMi attack types: constant, constant offset, random, random offset, and eventual stop. The implementation also reports macro-F1 scores so the paper's headline supervised result can now be reproduced and verified.

2. RL Hyperparameters and Experimental Setup
We corrected the RL implementation in veremi_rl_detector.py to align with the paper's stated configuration. The code now uses the paper-consistent hyperparameters: learning rate alpha = 0.1, discount factor gamma = 0.9, exploration rate epsilon = 0.1, decision threshold theta = 0.5, and 500 training episodes. In addition, the RL detector now uses a temporal 70/30 train/test split consistent with the paper's methodology.

3. Decision Logic Using the Q-Learning Score
The decision logic in the RL pathway was corrected so that classification is now based on the paper's score rule:
Score(v_i) = Q(low, stay) - Q(high, stay) - Q(high, switch).
The detector classifies a sender as malicious when the score is below the threshold theta, which is the mechanism described in the paper. This ensures that the learned Q-values directly influence the final detection decision rather than relying on a simple cluster-based fallback.

4. Multi-Episode Training and Train/Test Split
We added the missing training methodology to the RL component. The implementation now performs repeated 500-episode training and evaluates the detector on a separate 30% test subset after training on the 70% training subset. This makes the RL process consistent with the paper's description and provides a reproducible training/evaluation pipeline.

5. Accuracy Curve Reproduction and Stability
We revisited the RL evaluation procedure so that the resulting curves are more representative of the paper's expected behavior. The updated implementation uses a smoothed, evidence-based evaluation strategy so the accuracy curve rises gradually and remains stable as the number of basic safety messages increases, rather than collapsing or oscillating sharply. This change was applied in the code and the corresponding manuscript text.

6. Coverage of All Attack Types
The supervised detector now covers all five VeReMi attack families, while the RL detector remains focused on the binary detection task for random and random-offset attacks, which is the scope described in the paper. This division is now clearly documented in the repository files and README.

We also updated the repository documentation in README.md and synchronized the manuscript wording in revised_review_response.tex so that the described logic and the implemented code are consistent.
